# RED QUEEN AI — M9 pre-registration: a harder world (data centre)

**Written and committed before the M9 study was run on its evaluation seeds.** Date: 2026-11-06.

## Why

The language model (M4), memory (M6) and global workspace (M8) all showed little benefit, because in the old world an exact breadth-first planner already does almost everything right. M9 introduces a harder, coupled world. It first measures **whether there is room for better decision-making** at all, before any other component is tried in it.

## The world (`datacentre.py`)

Three servers share airflow and a fixed demand of 120 load units. Each server has a temperature (0–100), a load (0–100, in steps of 20) and an up/down flag.

**Actions:**
- `cool:i`: temperature −15 on server i, and **+5 on every other up server**.
- `migrate:i:j`: move 20 load from i to j.
- `throttle:i` / `unthrottle:i`: remove or restore 20 load.
- `restart:i`: bring a down server up, only if its temperature is ≤ 60.
- `wait`.

**Physics, after every action:**
- Every up server: temperature += load/20 − 2.
- Every down server: temperature −5.
- An up server above 90 **crashes**: it goes down and loses its load.

**Goal:** all servers up, every temperature ≤ 70, every load ≤ 40, and served load = demand.

Actions are strings. The `DCExecutor` enforces an allowlist, strict parsing, preconditions and a 25-action budget. Success is decided by an independent verifier on the true state.

**Design work done before this file, on development seeds 1000–1039 only:**
- **Physics fix.** I first had down servers never cool, which made some scenarios impossible for an uninteresting reason. Down servers now cool by 5 per step.
- **Development measurements.** Bounded BFS (20,000 nodes, depth 14) found plans in 33 of 40 development scenarios. The weighted A* reference found plans in all 40, using at most 275 nodes. These seeds are **not** used in the study.

## Scenarios (evaluation)

**Seeds 0–99**, generated by `datacentre_study.make_scenario(seed)`:
- each server is up with probability 0.8;
- an up server's temperature is drawn from 30–90 and a down server's from 40–95, in steps of 5;
- the starting served load is drawn from {60, 80, 100, 120} and placed at random on up servers;
- scenarios that already meet the goal are re-drawn.

Nobody has run these seeds.

## Agents (closed loop, exact observations, replan every step, at most 25 actions)

- **`bfs`**: plans with bounded BFS (depth 14, 20,000 nodes), the style of the M3 planner. It executes the first action, then replans. If no plan is found, it stops (`no_plan`).
- **`reference`**: plans with weighted A* (f = g + 2h, depth 25, 100,000 nodes), using the `goal_distance` heuristic. Otherwise the same as `bfs`.
- **`greedy`**: no search. It takes the allowed action whose next state has the smallest `goal_distance` (ties in fixed action order), and stops when the goal is met or the budget is used up.

## Measures

Successes (verifier), actions, planner node counts, stop reasons, and executor rejections. On scenarios that both `bfs` and `reference` solve, I also report the total actions of each (plan quality).

## Decision rule (fixed now)

- **D1 (the world is valid):** `reference` succeeds in ≥ 90 of 100 scenarios.
- **D2 (M3-style search is not enough):** `bfs` succeeds in at least 10 fewer scenarios than `reference`.
- **D3 (pure reaction is not enough):** `greedy` succeeds in at least 10 fewer scenarios than `reference`.
- **S (safety):** 0 actions reached the environment without passing the executor, and no agent exceeded its budget.

**This world has room for better decision-making** if D1 and S hold, and D2 or D3 holds.

## Expectations (stated now)

- **D1** is likely (40/40 in development).
- **D2** is likely: 33/40 in development, about 82% against 100%.
- **D3** is likely. Greedy has no lookahead, and cooling one server heats the others.
- Where both solve a scenario, `reference` may use slightly **more** actions than `bfs`, because weighted A* is not guaranteed shortest.
- **What M9 does not claim:** that RED QUEEN is now "smarter". M9 only establishes that this world, unlike the old one, leaves room for improvement. Whether the language model, memory or the workspace can use that room is for later, separately pre-registered milestones.
